# канген в поиске услуг

## Решение

```
запрос
  -> текстовый скор каждого объявления корпуса: BM25 + символьные триграммы + косинус дообученного bi-encoder
  -> приоритет по локации: свой город -> соседний (по переходам из трейна) -> остальные, внутри каждой группы совпал ли вид услуги с фильтром запроса
  -> топ-300 в порядке "приоритет по локации, потом скор"
  -> логистическая регрессия над 22 признаками кандидата (скоры, группа по локации, рейтинг, отзывы, цена, длины текстов)
  -> первые 50
```

Почему именно так в `docs/architecture.md` разбор данных, обоснование каждого шага, все замеры и журнал попыток.

## Результаты

| попытка | схема | валидация | лидерборд |
|---|---|---|---|
| 1 | BM25 + фильтр + локация, топ-200 | 0,537 | 0,488 |
| 2 | BM25 по всему корпусу + приоритет по локации | 0,851 | 0,80 |
| 3 | + дообученный dense с приоритетом по локации | 0,896 | 0,868 |
| 4 | + логрег-реранкер | 0,910 | **0,875** |

Валидация: 2500 запросов из трейна (37% с текстом, который остается в трейне, как в бенчмарке), корпус объявления бенчмарка плюс позитивы этих запросов. Она оптимистичнее лидерборда на 3 5 пунктов: в первой версии сплита объявления валидации оставались в трейне для других запросов, и модель видела их тексты на обучении. сплит исправлен (`src/split.py`, раздел 13 в `docs/architecture.md`) но модель в `data/models/` обучена на первой версии переобучить до сдачи не успели. лидерборд от этого не зависит.

## Как запустить

Python 3.12, зависимости в `requirements.txt`. Данные три parquet-файла в `data/raw/`.

```bash
uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python -r requirements.txt
.venv/bin/python predict.py
```

Результат `answer.csv` в корне.

### Модель

Дообученные веса (1,4 ГБ) в репозиторий не помещаются, скачать архив: https://disk.360.yandex.ru/d/X68GTJT_nbdFYA

распаковать в `data/models/`, чтобы получилась папка `data/models/user-bge-m3-ft1/`:

```bash
unzip user-bge-m3-ft1.zip -d data/models/
```
 Реранкер `data/models/rerank_logreg.pkl` лежит в репозитории.

чтобы получить модель самому: `.venv/bin/python train.py` около 4 часов на M4 Pro, чекпойнты каждые 40 шагов, при повторном запуске продолжает с последнего. данные для обучения (`data/processed/`) собирает блокнот `notebooks/02_dense_zero_shot.ipynb` через `src/split.py`. реранкер: `.venv/bin/python train_rerank.py` собирает признаки по валидации (`src/rerank.py`), показывает оценку по 5 фолдам и сохраняет `data/models/rerank_logreg.pkl`; около двух минут при готовых эмбеддингах.

## Что где лежит

| | |
|---|---|
| `src/params.py` | разбор `infm_params_text`: параметры склеены в строку без разделителей, режем по словарю названий |
| `src/text.py` | как запрос и объявление превращаются в текст для модели |
| `src/lexical.py` | BM25 по трем полям с лемматизацией pymorphy |
| `src/ranking.py` | приоритет по локации (свой город -> соседний -> остальные), триграммы, популярность, сборка топ-50 |
| `src/rerank.py` | признаки кандидатов для реранкера |
| `src/split.py`, `src/metrics.py`, `src/search.py` | валидация, Recall@K, точный поиск по эмбеддингам |
| `train.py`, `train_rerank.py`, `eval_model.py`, `predict.py` | обучение модели и реранкера, оценка, сборка ответа |
| `notebooks/01…05` | разбор данных -> zero-shot -> BM25 -> структурные сигналы -> файнтюн; с выводами |
| `docs/architecture.md` | архитектура, обоснования, журнал всех замеров |

## Open-source

Модели (скачиваются с HuggingFace один раз, дальше все локально, внешних API нет):
- `deepvk/USER-bge-m3` предобученный bi-encoder, дообучен на парах из `train.parquet` (InfoNCE с in-batch негативами, GradCache).

библиотеки: sentence-transformers, transformers, torch, bm25s, pymorphy3, scikit-learn (логистическая регрессия), polars, numpy.
